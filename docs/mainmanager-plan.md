# 기획안 · 포스팅 일정 · 자동/반자동 안내 (mainmanager 전담)

이 문서는 **모든 게시물의 기획안(무슨 주제), 포스팅 일정(언제), 채널별 자동/반자동
안내(어떻게)를 한 곳에 모은 mainmanager 전담 문서**다. 이전에는 이 내용이
`content-playbook.md`·`publishing-plan.md`·`CLAUDE.md`·mainmanager 스킬 파일 자체에
조금씩 중복되어 있었는데, 여기로 통합했다. 다른 문서와의 역할 분담:

- **콘텐츠를 어떻게 만드는가**(원고 규칙·이미지 규칙·스토리보드 규칙) → `content-playbook.md`
- **자동 발행이 기술적으로 어떻게 구현됐는가**(코드 위치·자격증명·API 세부사항) → `publishing-plan.md`
- **무엇을, 언제, 자동/반자동 중 어느 방식으로 낼지, 다음 순번이 뭔지** → 이 문서
  (mainmanager가 관리하고, 사용자와의 일정/주제 확인도 이 문서 기준으로 한다)

## 1. 채널별 자동/반자동 안내 (절대 임의로 바꾸지 않는다)

| 채널 | 방식 | 비고 |
|---|---|---|
| 구글 블로그 (Blogger) | **완전자동 (API)** | GitHub Actions가 목요일 09:00 KST에 직접 발행 |
| 유튜브 쇼츠 | **완전자동 (API)** | 위와 같은 시각에 직접 업로드 |
| 페이스북 (페이지 게시글 · 릴스) | **완전자동 (API)** | 위와 같은 시각에 직접 발행 |
| 인스타그램 (캐러셀 · 릴스) | **완전자동 (API)** | 위와 같은 시각에 직접 발행 |
| 네이버 블로그 | 반자동 | 원고는 자동 준비, 발행은 사람이 월요일에 네이버 블로그 자체 예약발행(목 09:00)으로 등록 |
| 유튜브 커뮤니티 게시판 | 반자동 | Data API 미지원 — 사람이 목요일 직접 게시 |
| 네이버클립 | 반자동 | 업로드 API 없음 — 사람이 토요일 직접 업로드 |
| 당근마켓 · 카카오톡채널 · 네이버플레이스 | 반자동 | 예약 기능 없음/신뢰도 낮음 — 사람이 금요일 직접 게시 |
| 스레드 | 보류(반자동으로 시작) | 콘텐츠 전략 확정 전. 별도 Meta 앱으로 나중에 완전자동 전환 가능 |

완전자동 4채널(구글 블로그·유튜브 쇼츠·페이스북·인스타그램)은 GitHub Actions가 API를
직접 호출해 발행하므로 사람이 로그인할 필요가 없다. 반자동 채널은 콘텐츠까지만 자동
준비되고, 발행 클릭은 항상 사람이 한다. 구현 세부사항(코드·자격증명)은
`publishing-plan.md` §1 참고.

## 2. 주간 포스팅 일정 — 블로그/카드뉴스/숏츠 파이프라인

| 요일 | 할 일 / 확인할 것 |
|---|---|
| 월요일 오전 | 이번 주 블로그 주제 확정(§5 참고) → 원고 작성 착수. 네이버 블로그는 사람이 자체 예약발행(목 09:00)으로 등록. **주간 교육뉴스**(education-news-weekly, 별개 파이프라인)도 같은 날 주제 확정 후 발행 |
| 월요일 11:00 이후 | 블로그 원고 완성 → §6 승인 게이트 통과 후에만 카드뉴스·숏츠 스토리보드 + 스레드 초안 착수 |
| 화~수요일 | 클로드코드/HyperFrames 렌더링 대기 상태 확인 |
| 목요일 09:00 KST | GitHub Actions 자동 실행(구글블로그·페이스북·인스타그램·유튜브쇼츠 동시 발행) 결과 확인. 네이버 블로그는 월요일 예약이 같은 시각 공개. 유튜브 커뮤니티는 사람이 이 시점에 직접 게시 |
| 금요일 | 당근마켓·카카오톡채널·네이버플레이스·스레드 수동 게시 여부 확인 |
| 토요일 | 네이버클립 업로드 여부 확인 |

진행 상태는 `docs/blog-calendar.md`의 "진행 상황" 절에 기록/갱신한다(예: "7주차 —
원고 작성중", "6주차 — 렌더링 대기").

다음 순번 주제, 22주 편집 일정, 진행 상황은 **[docs/blog-calendar.md](blog-calendar.md)**
를 따른다. 홍보형(P)과 정보형(I/L/M)을 번갈아 배치하는 원칙, 정보형은 시의성 우선
배치 원칙을 유지한다. 순서를 앞당기거나 미루는 게 좋겠다고 판단되면 사용자에게
제안한다 — **mainmanager가 순서를 마음대로 바꾸지 않고, 항상 사용자 승인 후에만
`blog-calendar.md`를 수정한다.**

## 5. 월요일 주제 확정 절차 (신설)

매주 월요일 아침 브리핑에서 mainmanager는:

1. `docs/blog-calendar.md`에서 이번 주 예정 주제(다음 순번)를, `docs/education-news-log.md`에서
   교육뉴스 다음 호 후보(유력 1건)를 각각 확인해 사용자에게 제시한다.
2. "이대로 진행할까요, 아니면 더 나은 주제를 검색해볼까요?" 라고 물어 확인을 받는다.
3. 사용자가 "그대로 진행"이라고 하면 그 주제로 바로 원고/큐레이션 작성에 들어간다.
4. 사용자가 "다른 주제를 찾아봐" 등으로 요청하면, 최신 뉴스·입시 일정을 검색해 2~4개
   대안 후보를 요약과 함께 제시하고 사용자의 선택을 기다린다 — mainmanager가 임의로
   주제를 확정하지 않는다.
5. 최종 확정된 주제만 `docs/blog-calendar.md`(순서 변경 시) 또는
   `docs/education-news-log.md`(다음 호 후보 갱신 시)에 반영한다.

## 6. 결과물 보고 및 승인 게이트 (신설)

블로그 원고(+이미지)가 완성되면:

1. mainmanager(또는 실제 작성을 수행한 세션)는 그 결과물(제목·요약·원고 링크/내용)을
   사용자에게 보고한다.
2. "카드뉴스·숏츠 스토리보드 작성으로 진행할까요?"라고 물어 승인을 받는다
   (`content-playbook.md` §0의 워크플로 규칙과 동일한 게이트).
3. **사용자 승인이 없으면 다음 과정(카드뉴스/숏츠 스토리보드 착수)으로 진행하지
   않는다.** 승인이 늦어지거나 없으면 그 상태로 대기하고, 다음 브리핑 때 "승인
   대기중"으로 안내한다.
4. 사용자가 범위를 좁히면(예: "숏츠만") 그 범위만 진행한다.
