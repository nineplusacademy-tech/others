# ChatGPT 자문 협업 원칙 (2026-11-16 신설)

이 문서는 ChatGPT를 **독립적인 기술·기획·마케팅 자문 및 검토자**로 쓰는 방법을 정한다. 작업 흐름을 바꾸지 않고, 중요한 단계에서만 외부 시각을 받는 것이 목적이다.

## 1. 역할 분담

| 주체 | 역할 |
|---|---|
| Claude Code | 프로젝트의 **주도적인 실행자**. 분석·설계·구현·콘텐츠 제작·발행 준비를 맡고 자문 요청서를 쓴다 |
| ChatGPT | **독립적인 자문·검토자**. 방향·구현 방법·결과물 품질을 검토하고 개선 의견만 낸다. 실행을 대신하거나 작업 흐름을 바꾸지 않는다 |
| 사용자 | **최종 의사결정자**. 자문 전달, 의견 채택, 주요 변경 승인 |

## 2. 이 문서와 기존 교차검토(운영 개요 규칙 16)의 관계

| | 콘텐츠 교차검토 (규칙 16) | 프로젝트 자문 (이 문서) |
|---|---|---|
| 대상 | **게시될 콘텐츠의 텍스트**(교육뉴스·블로그 원고, 카드뉴스·숏츠 나레이션·자막·캡션 등) | **프로젝트 자체**(자동화 구조, 운영 체계, 마케팅·콘텐츠 전략, 디자인·UX, 어려운 문제) |
| 시점 | 게시 직전(큐 등록·렌더링 전) | 설계 전, 큰 구조 변경 전, 주요 기능 완성 후 등 |
| 기준 | 사실성 · 채널 적합성 · 게시 목적(학원 광고) 적합성 | 작업별로 요청서에 적은 검토 질문 |
| 양식 | 로컬 `C:\Users\user\Desktop\cross-review\make_packet.py` | [`ADVISORY_REQUEST.md`](ADVISORY_REQUEST.md) |
| 반영 원칙 | 사실 지적은 1차 출처 재확인 후 반영, 개선사항은 적극 검토해 수정 | 아래 §6 |

두 체계는 **겹치지 않게 따로 운영**한다. 콘텐츠 한 편의 문구 검토는 규칙 16을 쓰고, 방식·구조·전략은 이 문서를 쓴다. 규칙 16의 내용은 이 문서가 바꾸지 않는다.

## 3. 자문을 요청하는 시점

다음 상황에서는 자문 요청서를 작성하거나 갱신한다.

- 새로운 기능을 설계하기 전
- 중요한 기술적 구조를 결정하기 전
- 기존 기능의 구조를 크게 변경하기 전
- 디자인 및 사용자 경험을 개선할 때
- SNS 마케팅 및 콘텐츠 제작 전략을 수립할 때
- 오류나 해결하기 어려운 문제가 발생했을 때
- 주요 기능을 완성했을 때
- 최종 결과물의 품질을 검토할 때

**요청하지 않는 경우**: 오탈자·문구 수정, 한 회차 콘텐츠의 일상 제작, 이미 정해진 절차의 반복 실행, 요청서를 쓰는 데 드는 시간이 결과보다 큰 사소한 수정. 요청서는 **실제로 외부 검토가 도움이 되는 단계에 집중**한다. 판단이 애매하면 사용자에게 한 줄로 묻는다.

## 4. 요청 절차

1. **필요성 판단**: §3에 해당하는지, 지금 자문이 의사결정을 바꿀 수 있는지 확인한다.
2. **요청서 작성**: [`ADVISORY_REQUEST.md`](ADVISORY_REQUEST.md) 양식으로 쓴다. 추측이 아니라 **실제 구현 상태**를 적는다(파일 경로, 핵심 코드, 실행 결과, 오류 메시지).
3. **전달 전 점검**: §5의 금지 정보가 없는지 확인한다.
4. **전달**: 현재 크레딧이 없어 **수동 방식**이다 — 요청서 파일을 사용자에게 보내고, 사용자가 chatgpt.com에 붙여넣어 답을 채팅에 전달한다. 크레딧을 충전하면 로컬 `cross_review.py`로 자동 호출할 수 있다.
5. **의견 검토**: §6 원칙으로 항목마다 채택·부분 채택·미채택을 판단하고 표로 정리해 사용자에게 보인다.
6. **승인과 실행**: 주요 변경은 사용자 승인 뒤에만 한다. 승인된 것만 실행한다.
7. **기록**: [`PROJECT_STATUS.md`](PROJECT_STATUS.md)의 "자문 이력"과 "주요 의사결정"에 요청·판단·이유를 남긴다.

## 5. ChatGPT에 보내지 않는 정보

- API 키·토큰·비밀번호·Secrets 값, 계정 식별 정보
- 학생·학부모의 이름·연락처·성적 등 개인정보(학생 얼굴 사진 포함)
- 연락처·전화번호가 들어간 파일(콘텐츠 하단 연락처 블록 등)
- 결제·계정 설정 화면, 광고비 집행 정보

이 저장소는 공개 범위가 넓을 수 있으므로(블로그 이미지가 저장소 주소로 제공됨) 요청서와 상태 문서에도 위 정보를 적지 않는다.

## 6. ChatGPT 의견을 반영하는 원칙

- 제안은 **독립적인 검토 의견**으로 취급한다. 무조건 적용하지 않고 현재 프로젝트와의 적합성을 판단한다.
- 사실·법규 지적은 **1차 출처로 재확인한 뒤에만** 반영한다. 확인되지 않거나 출처 주소가 죽은 지적은 반영하지 않는다.
- 적용할 경우 **기대 효과와 변경 범위**를 확인해 사용자에게 보인다.
- 적용하지 않을 경우 **이유를 기록**한다(PROJECT_STATUS.md).
- **주요 변경은 사용자에게 보고하고 승인**받는다.
- 사용자가 승인하지 않은 **대규모 구조 변경이나 핵심 기능 삭제는 하지 않는다.**
- 기존 지침과 충돌하면 기존 지침(`CLAUDE.md`, `operations-overview.md`, 법규 한계선)이 우선이다. 충돌하는 제안은 사용자에게 알리고 판단을 맡긴다.
- 콘텐츠 교차검토(규칙 16)의 "개선사항은 적극 검토해 수정" 원칙은 그대로 유지한다.
