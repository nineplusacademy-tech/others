### 미완성·제한
- 네이버 블로그·플레이스·클립 **완전 수동** (자동화 불가), 네이버 주소를 받아야 스레드·페이스북·캡션 링크가 채워진다.
- 카카오 영상 업로드 수동, 교육뉴스 일부 채널 반자동.
- 교차검토 자동 호출은 OpenAI 크레딧이 없어 **수동 방식**으로 운영 중.
- 성과 측정은 팔로워 수 주간 기록과 순위·인사이트 조회 수준이며, **광고 전환(댓글 '9' → DM → 상담) 추적은 정량화되어 있지 않다.**
- 자동 테스트가 없고(`verify_secrets.py`로 자격증명만 점검), 큐 발행 로직은 실행 결과와 로그 확인에 의존한다.
- 구글 블로그(blogspot)는 서치콘솔에 별도 등록되지 않았다(미러 용도).

## 6. 잠재적 문제점과 개선 가능성

1. **성과 측정 부재**: 게시 목적이 광고인데 팔로우·댓글 '9'·DM·상담 전환을 연결해 보는 지표가 없다. 주제와 형식(카드뉴스·숏츠·블로그)별 효과를 비교하기 어렵다.
2. **문서 중복과 불일치 위험**: `operations-overview`, `mainmanager-plan`, `publishing-plan`, `content-playbook`, 스킬 문서에 같은 규칙이 여러 번 적혀 있다. 기준 문서를 먼저 고치는 규칙이 있지만 사람이 놓치기 쉽다. `content-playbook.md`는 이력이 많아 길다.
3. **로컬 결과물 백업**: 원고·이미지·영상이 로컬에만 있다. 디스크 장애 시 복구 수단이 없다(큐는 발행 후 삭제).
4. **저장소 공개 범위(2026-11-16 확인)**: 저장소는 **공개(public)**이고 `queue/` 파일도 비로그인으로 열린다(GitHub API `private:false`, raw 주소 200). 발행 전 초안이 미리 보일 수 있고 큐 삭제 뒤에도 커밋 히스토리에 남는다(히스토리 정리 계획은 별도, 승인 필요). 비공개로 바꾸면 블로그 게시물의 이미지 주소가 깨지므로 **공개 상태를 유지**하고, 큐에는 발행 직전의 공개 예정 내용만 올리며 비공개 정보를 넣지 않는다.
5. **제작 병목**: 숏츠는 Flow 클립·TTS·렌더링(채널당 수 분~수십 분)에 사람 개입이 필요하고, Gemini TTS가 가끔 응답하지 않는다(11/16에 특히 심했음).
6. **브라우저 자동화의 취약성**: KittyChat·당근·카카오·밴드 반자동은 화면 구조가 바뀌면 깨진다. KittyChat은 수정 아이콘 사고 전례가 있다.
7. **자동 테스트 없음**: 발행 코드는 DRY_RUN과 사후 점검에 의존한다.
