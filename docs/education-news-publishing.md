# 교육뉴스 발행 자동화 (구글 블로그 채널만)

`education-news-team`(이 저장소 스킬, [.claude/skills/education-news-team/SKILL.md](../.claude/skills/education-news-team/SKILL.md)
참고)이 mainmanager의 지시를 받아 매주 만드는 교육뉴스 큐레이션은 8개 채널에
배포되지만, 공식 발행 API가 있는 채널은 **구글 블로그(Blogger API)뿐**이다 — 나머지
7채널(네이버 밴드·네이버 블로그·유튜브 커뮤니티·당근마켓·카카오톡채널·네이버플레이스,
그리고 유튜브 동영상 설명란)은 메인 블로그 파이프라인에서 이미 확인한 것과 같은
이유(공식 API 부재/신뢰도 낮음)로 계속 사람이 로컬 산출물을 보고 체크리스트대로
직접 게시한다.

이 문서는 그 한 채널(구글 블로그)만 메인 파이프라인의 `queue/` 와 동일한 방식으로
자동 발행하는 구조를 설명한다. **주제 선정과 원고 승인은 그대로 사람이 한다** —
자동화되는 건 "승인된 원고를 실제로 Blogger에 올리는 버튼 클릭"뿐이다.

## 흐름

1. 매주, mainmanager 브리핑에서 교육뉴스 다음 호 후보를 제시하고 사용자
   승인을 받는다(`docs/mainmanager-plan.md` §5).
2. mainmanager가 `education-news-team` 스킬을 호출해 확정된 주제를 전달하면, 이
   스킬이 발행이력.md 중복 체크·최신 뉴스 검색을 거쳐 그 주 10개 파일(마스터본 3종 +
   채널별 배포본 5종 + 업로드 체크리스트 1종 + 삽화 1장)을 로컬
   `클로드작업폴더/교육뉴스/`에 작성한다(`education-news-team/SKILL.md` §1~§2).
3. 완성된 원고를 사용자에게 보고하고 발행 승인을 받는다(메인 블로그 파이프라인의
   승인 게이트와 동일한 원칙 — 사실 기반 콘텐츠라 사람 확인 없이 발행하지 않는다).
4. **승인 후에만**, `교육뉴스_YYYY-MM-DD_구글블로그.html`의 내용을 아래 형식에 맞춰
   `queue-edu/<YYYY-MM-DD>_<주제요약>/구글블로그용.md` 로 저장해 이 저장소에 커밋·
   푸시한다(로컬 원본은 그대로 둔 채 복사만 — 메인 파이프라인의 `queue/`와 동일한
   패턴).
5. 발행 워크플로(`.github/workflows/publish-edu.yml`)가 **화요일 10:00 KST**(메인
   블로그와 동시, 2026-09-08 변경 — 이전 월요일 12:00 KST)에 자동 실행되거나, 그전에
   급하면 `workflow_dispatch`로 즉시 실행할 수 있다 — `queue-edu/` 폴더 하나를 찾아
   Blogger API로 게시하고, 성공하면 그 폴더를 삭제하는 커밋을 자동으로 만든다.
6. 나머지 7채널은 이 큐와 무관하게, 사용자가 로컬 산출물(밴드용 텍스트·당근소식·
   네이버플레이스소식·유튜브커뮤니티·유튜브설명란 등)을 보고 업로드체크리스트대로
   직접 게시한다.
7. 구글 블로그 발행이 성공해 `queue-edu/`가 비워지면(=queue-edu 폴더가 사라지면),
   `docs/mainmanager-plan.md` §7 규칙대로 mainmanager가 `docs/education-news-log.md`를
   즉시 갱신한다(다룬 주제로 기록 + 다음 호 후보 정리).

## `구글블로그용.md` 형식 (`scripts/publish/main_edu.py`가 이 형식 그대로 읽는다)

메인 블로그 파이프라인과 완전히 동일한 형식(YAML 프런트매터 + HTML 본문)이다 —
`교육뉴스_YYYY-MM-DD_구글블로그.html`(순수 HTML 조각)의 내용을 그대로 본문에 붙이고,
제목·라벨만 프런트매터로 추가하면 된다.

```markdown
---
title: 포스트 제목
labels: [교육뉴스]
---
<h2>소제목</h2>
<p>본문...</p>
```

- `labels`를 생략하면 `main_edu.py`가 기본값 `["교육뉴스"]`를 붙인다.
- **가정**: 교육뉴스도 메인 콘텐츠와 같은 Blogger 블로그(`BLOGGER_BLOG_ID` 시크릿 공유)에
  라벨로만 구분해서 올라간다고 가정했다 — 별도 블로그를 원하면 알려주면 시크릿을
  분리(`EDU_BLOGGER_BLOG_ID` 등)하도록 바꿀 수 있다.

## 실제 구현 위치

- `scripts/publish/main_edu.py` — `queue-edu/` 폴더 하나를 찾아 `scripts/publish/blogger.py`의
  `publish()`를 그대로 재사용해 발행. 채널이 하나뿐이라 `main.py`처럼 병렬화·단계별
  상태 파일이 필요 없다.
- `.github/workflows/publish-edu.yml` — 매주 화요일 01:00 UTC(10:00 KST) 실행(메인
  블로그의 `--phase blog` 배치와 동시) + `workflow_dispatch`로 즉시 실행 가능.
  `queue-edu/`가 비어있으면(아직 승인 전) 조용히 "발행할 콘텐츠 없음"으로 끝난다.
- 자격증명은 메인 파이프라인과 동일한 Secrets(`GOOGLE_OAUTH_CLIENT_ID` 등,
  `BLOGGER_BLOG_ID`)를 그대로 재사용 — 새로 등록할 시크릿은 없다.

## 하단 CTA·해시태그 방침 (2026-09-08 확정 — 순수 정보성 유지)

교육뉴스는 **전 채널에서 학원 CTA(상담 유도·홈페이지·전화·주소·관련 학교 등)와 학원법상
법정 고시사항 블록을 넣지 않는다** — 메인 블로그(`content-playbook.md` §4)와 달리, 교육뉴스는
순수 정보 전달을 목적으로 발행한다. 발행처를 밝히는 "나인플러스학원 | 주소" 한 줄 서명
정도만 유지하고, 상담·문의를 직접 권유하는 문구는 넣지 않는다.

대신 **모든 채널(카카오톡채널 포함)에 해시태그를 적절히 달아 블로그 유입을 간접적으로
유도**한다 — 브랜드 태그(#나인플러스학원 #수원학원 #우만동학원 #나인플러스학원블로그)와
그 호의 주제 태그(예: #9월모의평가 #수시원서접수)를 함께 단다. 해시태그만으로는 직접적인
상담 유도가 아니므로 정보통신망법상 "광고성 정보"(메시지 첫머리 "(광고)" 표기+수신거부
안내 의무)로 분류될 위험 없이, 검색 노출을 통해 자연스럽게 블로그로의 유입을 늘리는
간접 홍보 방식이다.

한때(2026-09-08 초) 블로그와 동일한 전체 CTA+고시사항 블록을 카카오톡채널을 제외한
전 채널에 넣는 방향으로 진행했다가, 같은 날 "교육뉴스는 순수 정보성으로 가고 해시태그로
간접 홍보하자"는 방향으로 다시 확정했다 — 이 절이 최종 방침이다.

2026-09-08 이후로는 `education-news-team`이 이 저장소 스킬이라 이 방침이 스킬 정의
자체(§3)에 이미 포함돼 있다 — 예전 계정 레벨 스킬 때처럼 별도로 동기화해줄 필요가
없다.

## 콘텐츠 저장 원칙과의 관계

교육뉴스 산출물은 여전히 평소 로컬 `클로드작업폴더/교육뉴스/`에만 보관한다. 이
저장소에는 **발행 승인 후, Blogger에 자동 올리기 직전에만** `queue-edu/` 폴더가
잠깐 생겼다가, 발행 성공 즉시 삭제된다 — 메인 블로그 파이프라인의 `queue/`와 완전히
같은 원칙(`docs/publishing-plan.md` §2 참고)이다.
