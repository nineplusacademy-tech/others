# 교육뉴스 발행 자동화 (구글 블로그 채널만)

`education-news-weekly`(계정 레벨 스킬, [docs/education-news-log.md](education-news-log.md)
참고)로 매주 월요일 만드는 교육뉴스 큐레이션은 8개 채널에 배포되지만, 공식 발행 API가
있는 채널은 **구글 블로그(Blogger API)뿐**이다 — 나머지 7채널(네이버 밴드·네이버
블로그·유튜브 커뮤니티·당근마켓·카카오톡채널·네이버플레이스, 그리고 유튜브 동영상
설명란)은 메인 블로그 파이프라인에서 이미 확인한 것과 같은 이유(공식 API 부재/신뢰도
낮음)로 계속 사람이 로컬 산출물을 보고 체크리스트대로 직접 게시한다.

이 문서는 그 한 채널(구글 블로그)만 메인 파이프라인의 `queue/` 와 동일한 방식으로
자동 발행하는 구조를 설명한다. **주제 선정과 원고 승인은 그대로 사람이 한다** —
자동화되는 건 "승인된 원고를 실제로 Blogger에 올리는 버튼 클릭"뿐이다.

## 흐름

1. 매주 월요일, mainmanager 브리핑에서 교육뉴스 다음 호 후보를 제시하고 사용자
   승인을 받는다(`docs/mainmanager-plan.md` §5).
2. 사용자가 로컬에서 `education-news-weekly` 스킬로 그 주 10개 파일(마스터본 3종 +
   채널별 배포본 6종 + 업로드 체크리스트)을 작성한다 — 이 단계는 지금까지와 동일하고
   바뀌지 않는다.
3. 완성된 원고를 사용자에게 보고하고 발행 승인을 받는다(메인 블로그 파이프라인의
   승인 게이트와 동일한 원칙 — 사실 기반 콘텐츠라 사람 확인 없이 발행하지 않는다).
4. **승인 후에만**, `교육뉴스_YYYY-MM-DD_구글블로그.html`의 내용을 아래 형식에 맞춰
   `queue-edu/<YYYY-MM-DD>_<주제요약>/구글블로그용.md` 로 저장해 이 저장소에 커밋·
   푸시한다(로컬 원본은 그대로 둔 채 복사만 — 메인 파이프라인의 `queue/`와 동일한
   패턴).
5. 발행 워크플로(`.github/workflows/publish-edu.yml`)가 월요일 12:00 KST에 자동
   실행되거나, 그전에 급하면 `workflow_dispatch`로 즉시 실행할 수 있다 —
   `queue-edu/` 폴더 하나를 찾아 Blogger API로 게시하고, 성공하면 그 폴더를 삭제하는
   커밋을 자동으로 만든다.
6. 나머지 7채널은 이 큐와 무관하게, 사용자가 로컬 산출물(밴드용 텍스트·당근소식·
   네이버플레이스소식·유튜브커뮤니티·유튜브설명란 등)을 보고 업로드체크리스트대로
   직접 게시한다.
7. 구글 블로그 발행이 성공해 `queue-edu/`가 비워지면(=queue-edu 폴더가 사라지면),
   `docs/mainmanager-plan.md` §7 규칙대로 mainmanager가 `docs/education-news-log.md`를
   즉시 갱신한다(다룬 주제로 기록 + 다음 호 후보 정리).

## `구글블로그용.md` 형식 (`scripts/publish/main_edu.py`가 이 형식 그대로 읽는다)

메인 블로그 파이프라인과 완전히 동일한 형식(YAML 프런트매터 + HTML 본문)이다 —
`교육뉴스_YYYY-MM-DD_구글블로그.html`(순수 HTML 조각)의 내용을 그대로 본문에 붙이고,
제목·라벨만 프런트매터로 추가하면 된다.

```markdown
---
title: 포스트 제목
labels: [교육뉴스]
---
<h2>소제목</h2>
<p>본문...</p>
```

- `labels`를 생략하면 `main_edu.py`가 기본값 `["교육뉴스"]`를 붙인다.
- **가정**: 교육뉴스도 메인 콘텐츠와 같은 Blogger 블로그(`BLOGGER_BLOG_ID` 시크릿 공유)에
  라벨로만 구분해서 올라간다고 가정했다 — 별도 블로그를 원하면 알려주면 시크릿을
  분리(`EDU_BLOGGER_BLOG_ID` 등)하도록 바꿀 수 있다.

## 실제 구현 위치

- `scripts/publish/main_edu.py` — `queue-edu/` 폴더 하나를 찾아 `scripts/publish/blogger.py`의
  `publish()`를 그대로 재사용해 발행. 채널이 하나뿐이라 `main.py`처럼 병렬화·단계별
  상태 파일이 필요 없다.
- `.github/workflows/publish-edu.yml` — 매주 월요일 03:00 UTC(12:00 KST) 실행 +
  `workflow_dispatch`로 즉시 실행 가능. `queue-edu/`가 비어있으면(아직 승인 전) 조용히
  "발행할 콘텐츠 없음"으로 끝난다.
- 자격증명은 메인 파이프라인과 동일한 Secrets(`GOOGLE_OAUTH_CLIENT_ID` 등,
  `BLOGGER_BLOG_ID`)를 그대로 재사용 — 새로 등록할 시크릿은 없다.

## 콘텐츠 저장 원칙과의 관계

교육뉴스 산출물은 여전히 평소 로컬 `클로드작업폴더/교육뉴스/`에만 보관한다. 이
저장소에는 **발행 승인 후, Blogger에 자동 올리기 직전에만** `queue-edu/` 폴더가
잠깐 생겼다가, 발행 성공 즉시 삭제된다 — 메인 블로그 파이프라인의 `queue/`와 완전히
같은 원칙(`docs/publishing-plan.md` §2 참고)이다.
