# 운영 한눈에 보기 — 채널·역할·규칙 요약 (2026-11-07 정리)

이 문서는 **지금 실제로 돌아가는 방식만** 모은 한 장 요약이다. 변경 이력과 근거는 아래 "문서 지도"의 상세 문서에 그대로 남아 있고, 요약과 상세가 어긋나면 **이 문서를 먼저 고친 뒤 상세 문서를 맞춘다**.

방식은 세 가지로만 나눈다.

- **자동**: GitHub Actions가 API로 직접 올린다. 사람이 아무것도 하지 않는다(전제 조건만 맞추면 된다).
- **반자동**: 사용자 PC 크롬의 로그인 세션을 이용해 예약 작업 `semi-auto-posting`이 화면을 조작해 올린다. 사용자는 **로그인 유지와 파일 준비**만 한다.
- **수동**: 자동화 도구로 접근이 막히거나 API가 없어서 **사용자가 직접** 올린다(주로 네이버 계열).

## 4. 핵심 규칙(요약)

콘텐츠 제작
1. **블로그 원고가 출발점**이다. 카드뉴스·숏츠·스레드·페이스북 글은 그 원고에서 파생하고 원문과 어긋나지 않게 한다.
2. **타겟은 6개교**(동성중·동수원중·산남중·유신고·창현고·광교고) 학생·학부모다. 해시태그에 6개교 전체와 `#우만동학원`을 넣고, `#수원학원`처럼 넓은 태그는 쓰지 않는다.
3. 과장·허위 금지, 수치는 출처와 함께, 원장 경험은 "연구 결과가 아니다"를 밝힌다. 사용자가 확인해 준 내용만 쓰고 지어내지 않는다.
4. **개인정보**: 학생 얼굴·실명·성적표·다른 전화번호는 쓰지 않고 가린다.
5. 홍보형 블로그 하단에는 연락처 블록과 법정고시사항(제8065호/중등 월 35, 고등 월 59.2 만원)을 넣는다. **교육뉴스는 CTA·고시사항 없이 순수 정보성**이고 해시태그로만 유도한다.
6. 블로그·교육뉴스 끝에는 **이전 네이버 글 3개**("함께 읽어보면 좋은 글", 주소는 `docs/naver-blog-posts.md`에 있는 것만).
7. **카드뉴스**는 9~10장, 1080×1350, 글자는 하단 안전선(y≈1170) 위에만 둔다. 인스타 버전을 먼저 확인받은 뒤 나머지 채널을 만든다. 이미지 규칙은 남색+골드+흰색, 표지 후킹은 질문형으로 크게.
8. 캡션: 리스트는 줄을 바꾸고, `📝 원문 보기 👉 {{BLOG_URL}}`처럼 👉 줄은 URL을 같은 줄에 둔다. 발행에 들어가면 안 되는 메모는 `[※ …]`로 쓰되 `스레드.md`와 `캡션_유튜브쇼츠.md`에는 메모를 아예 넣지 않는다.
8-1. **캡션·유튜브 고정댓글·네이버클립 소개글에는 학원 홈페이지와 원문 주소만** 안내한다(2026-11-11 사용자 지시). 카카오톡 채널·네이버 톡톡 URL, 플레이스 링크, 전화, 주소 줄은 넣지 않는다. 블로그 본문의 연락처 블록과 KittyChat "9" DM 문구는 그대로다.
9. 댓글 "9"는 **인스타그램 전용** 안내다. 다른 채널에는 쓰지 않는다. 자동응답은 게시물마다 그 게시물에만 만든다.
10. 스토리용 이미지·영상은 82% 축소+블러 배경 세이프존 파일(`make_story_assets.py`)을 쓴다.

운영
11. 큐(`queue/`·`queue-edu/`)에는 **그 주 콘텐츠가 완성된 뒤 발행 직전에만** 올린다. 올리면 곧바로 commit+push하고, `git add`는 경로를 지정한다(미추적 파일이 딸려 올라가지 않게). 발행 성공하면 자동 삭제된다.
12. 실제 결과물(원고·이미지·영상)은 저장소에 두지 않고 로컬 `클로드작업폴더/`에만 둔다. API 키는 GitHub Secrets로만 관리한다.
13. 사진·클립을 사용자에게 요청할 때는 **프롬프트 복사 버튼과 업로드 칸이 있는 아티팩트**로 요청한다. 작업이 끝난 요청 아티팩트는 삭제한다(현황판·재사용하는 삽화 요청 제외).
14. **작업 현황판은 항상 최신**으로 유지한다(같은 링크, 상태가 바뀌면 바로 갱신).
15. 반자동 게시는 파일 원문 그대로 올리고, 비밀번호 입력·대량 메시지·임의 문구 추가를 하지 않으며, 한 채널에서 두 번 실패하면 멈추고 사용자에게 넘긴다.
