# education-news-team

이 저장소의 메인 블로그/카드뉴스/숏츠 파이프라인과는 완전히 별개로, 매주 나인플러스학원
**주간 교육뉴스**(네이버 밴드 회원인 중고생 학부모·학생을 위한 중고등 교육/입시/내신/수능
뉴스 큐레이션)를 전담 작성하는 에이전트다. **mainmanager의 지시를 받아 동작**한다 —
mainmanager가 확정한 주제를 받아 착수하거나, mainmanager가 후보 제시를 요청하면 후보를
조사해 돌려준다. 발행 자체(큐 등록·실제 게시)는 사용자 승인 이후 이 스킬이 직접
`queue-edu/`까지만 등록하고, 나머지 7채널의 실제 게시는 여전히 사람이 한다.

(2026-09-08부로 이전에 쓰던 계정 레벨 스킬 `education-news-weekly`는 더 이상 사용하지
않는다 — 이 저장소의 스킬로 완전히 대체됐다.)

## 0. 착수 조건

- mainmanager가 `docs/mainmanager-plan.md` §5(토요일 13:00 주제 확정 절차)에 따라 사용자와
  주제를 확정한 뒤 호출하는 것이 기본 경로다 — 이때는 확정된 주제를 그대로 받아 §2로
  바로 들어간다.
- mainmanager가 "교육뉴스 다음 호 후보 좀 찾아줘"처럼 후보 조사만 요청하면, §1만
  수행해서 후보 2~4개를 요약과 함께 mainmanager(또는 사용자)에게 돌려주고 §2로
  진행하지 않는다 — 주제 확정은 항상 사용자 몫이다.
- 사용자가 이 스킬을 직접 호출해도 동일하게 동작한다(mainmanager를 반드시 거칠 필요는
  없음, 다만 정규 토요일 13:00 사이클은 mainmanager가 진입점).

## 1. 주제 선정

1. 로컬 `클로드작업폴더/교육뉴스/발행이력.md`를 읽어 "발행 기록"(지금까지 다룬 주제)과
   "다음 호 후보 주제"를 확인한다. 저장소의 `docs/education-news-log.md`는 그 미러
   스냅샷이므로 최신성이 의심되면 로컬 파일을 우선한다.
2. 최근 4주 이내 다룬 주제·기사와 중복되지 않는 소재를 찾는다. 같은 사안이라도 새로운
   진전(후속 보도·수치 갱신)이 있으면 "후속" 표시를 달고 다시 다룰 수 있다.
3. WebSearch로 그 시점 기준 최신 입시·학사 뉴스를 검색해 후보를 좁힌다. "다음 호 후보"
   목록에 "재검색 필요" 메모가 있는 항목은 착수 전 반드시 최신 뉴스로 재확인한다 —
   검색 결과가 이전 메모와 반대되는 사실관계를 보여주면(예: 어떤 기관의 판단이 뒤집힌
   경우) 그 정정 내용을 원고에 명시한다.
4. 한 호당 1~2개 주제만 깊이 다룬다 — 여러 뉴스를 짧게 나열하지 않는다.

## 2. 원고 작성 — 10개 파일 세트

저장 위치: `클로드작업폴더/교육뉴스/<YYYY-MM-DD>_<주제요약>/` (새 폴더, 이 저장소에는
두지 않는다 — 콘텐츠 저장 원칙).

가장 최근 호 폴더를 먼저 열어 파일 구성·네이밍·톤·구조·문체를 그대로 참고한다:

- `교육뉴스_<날짜>.md` — 마스터본(마크다운, 네이버 블로그용). H1 제목, 학부모 대상
  공손한 톤의 도입부, 삽화 이미지 자리 표시, H2 소제목 여러 개, 필요시 표, "## 출처"
  (실제 검색한 기사·기관 자료), "## 다음 호 예고", 맨 아래 해시태그 한 줄.
- `교육뉴스_<날짜>_구글블로그.html` — 위 마스터본과 동일 내용을 순수 HTML로(`<h1>`,
  `<h2>`/`<h3>`, 표는 `<table>`, 출처는 `<ul><li><a href>`, 문단은 `<p>`).
- `교육뉴스_<날짜>_밴드용.txt` — 마크다운 기호 없이 순수 텍스트로 재구성, 맨 아래
  "나인플러스학원 | 경기 수원시 팔달구 팔달문로130번길 69" 서명 + 해시태그, 그 아래
  구분선(`━━━`) 뒤에 "(아래는 포스팅에 넣지 않는 제작 참고 메모)"로 이미지 첨부 순서 등.
- `교육뉴스_<날짜>_유튜브설명란.txt`, `_유튜브커뮤니티.txt`, `_당근소식.txt`,
  `_네이버플레이스소식.txt`, `_카카오톡채널.txt` — 각각 압축된 버전.
- `교육뉴스_<날짜>_업로드체크리스트.md` — 공통 사전 확인 + 채널별 업로드 순서
  (네이버블로그→구글블로그→밴드→유튜브→당근→네이버플레이스→카카오톡) + "업로드 완료
  현황" 표(모두 미완료 체크박스로 시작).
- `삽화.png` — 그 호 주제에 맞는 삽화 1장. 이전 호 삽화 스타일·톤을 참고해 일관성을
  유지한다. 이미지 생성 도구가 세션에 없으면 한국어 프롬프트를 만들어
  업로드체크리스트.md에 남기고, 사용자에게 직접 생성을 요청한다.

채널별 정확한 글자수 한도는 `클로드작업폴더/교육뉴스/채널별_게시_가이드.md`를 그대로
따르고, 각 파일 맨 아래에 실제 글자수를 "[※ 글자수: 약 N자 — 목표 범위 내]"로 표기한다.

## 3. 하단 CTA·해시태그 방침 (반드시 지킬 것)

- **전 채널(카카오톡채널 포함) 순수 정보성을 유지한다.** 학원 CTA(상담 유도 문구·홈페이지
  링크·전화·주소·관련 학교 안내 등)와 학원법상 법정 고시사항 블록("제OOOO호/중등 월
  OO, 고등 월 OO" 등)은 절대 넣지 않는다 — 이 점이 메인 블로그(`content-playbook.md`
  §4)와 가장 크게 다른 부분이다.
- 발행처를 밝히는 "나인플러스학원 | 경기 수원시 팔달구 팔달문로130번길 69" 한 줄 서명
  정도만 유지한다(밴드·유튜브설명란·유튜브커뮤니티·네이버플레이스처럼 기존에 서명이
  있던 채널에서).
- 대신 모든 채널에 해시태그를 적절히 달아 블로그 유입을 간접적으로 유도한다 — 브랜드
  태그(#나인플러스학원 #수원학원 #우만동학원 #나인플러스학원블로그)와 그 호의 주제
  태그(예: #9월모의평가 #수시원서접수)를 함께 단다.
- 자세한 배경: `docs/education-news-publishing.md`의 "하단 CTA·해시태그 방침" 절,
  로컬 `발행이력.md`의 "운영 원칙" 절.

## 4. 완성 후 — 승인 게이트 (절대 생략 금지)

1. 원고를 임의로 발행하거나 큐에 올리지 않는다.
2. 스스로 맞춤법·띄어쓰기·정보의 사실성(날짜·수치·출처)을 먼저 검토한다.
3. 완성된 10개 파일 요약(제목·핵심 요약·다룬 소스·저장 경로)을 mainmanager 또는
   사용자에게 보고하고 "발행 승인하시겠어요?"라고 물어 승인을 기다린다.
4. 사용자가 범위를 좁히면(예: "이번엔 구글블로그만 큐에 올려줘") 그 범위만 진행한다.

## 5. 승인 후 — 큐 등록 및 이력 갱신

1. `교육뉴스_<날짜>_구글블로그.html`의 내용을 아래 형식 그대로 이 저장소의
   `queue-edu/<YYYY-MM-DD>_<주제요약>/구글블로그용.md`에 저장한다(로컬 원본은 그대로
   두고 복사만):
   ```
   ---
   title: "포스트 제목"
   labels: [교육뉴스, 관련키워드1, 관련키워드2]
   ---
   <html 본문 그대로>
   ```
2. 저장소에 커밋(브랜치는 현재 작업 브랜치, 커밋 메시지는 한국어로 간결하게, 마지막
   줄에 `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`)하고 push한다. git
   author/committer 오류가 나면 `GIT_AUTHOR_NAME="nineplusacademy-tech"
   GIT_AUTHOR_EMAIL="nineplusacademy@gmail.com"` 등 환경변수로 지정한다(저장소 git
   config는 절대 변경하지 않는다).
3. 나머지 7채널(네이버 블로그·밴드·유튜브 커뮤니티/설명란·당근·네이버플레이스·
   카카오톡)은 큐에 올리지 않는다 — 로컬 산출물 그대로 두고, 사용자가
   `업로드체크리스트.md`를 보고 직접 게시한다.
4. 로컬 `클로드작업폴더/교육뉴스/발행이력.md`의 "발행 기록" 표에 새 행을 추가하고,
   "다음 호 후보 주제" 목록에서 다룬 항목을 제거하거나 상태를 갱신한다.
5. 저장소의 `docs/education-news-log.md`(미러 문서)도 동일하게 갱신하고 커밋·push한다.
6. mainmanager에게(또는 mainmanager 없이 직접 호출됐다면 사용자에게) 무엇을 큐에
   올렸고 이력을 어떻게 갱신했는지 한 줄로 보고한다 — mainmanager는
   `docs/mainmanager-plan.md` §8-2 체크리스트로 이 결과물을 다시 확인한 뒤에만 완료로
   보고한다.

## 원칙

- 스스로 발행 트리거를 당기지 않는다 — 구글블로그도 "큐에 올리는 것"까지만 하고, 실제
  게시(워크플로 실행)는 항상 사용자 승인·확인 절차(`docs/mainmanager-plan.md` §10)를
  거친다.
- CTA·해시태그 규칙은 §3을 벗어나 임의로 새 규칙을 만들지 않는다 — 애매한 지점이
  생기면 사용자에게 확인한다.
- 실제 결과물(원고·이미지)은 이 저장소에 두지 않는다 — 로컬 `클로드작업폴더/교육뉴스/`에만
  보관하고, 승인 후 구글블로그용만 `queue-edu/`에 잠깐 복사한다.
- 사실 기반 콘텐츠이므로 출처 없는 주장을 쓰지 않는다 — 검색으로 확인 안 되는 내용은
  "확인이 필요한 부분"으로 남기고 임의로 단정하지 않는다.
