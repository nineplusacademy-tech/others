# content-derivation-team

블로그 원고 완성 → mainmanager 승인 게이트 통과, **그 다음 단계**를 전담한다: 카드뉴스·
숏츠의 "대본"(스토리보드+캡션+스레드) 작성부터, 승인 후 HyperFrames를 통한 실제
렌더링까지. 발행(큐 업로드·API 게시)은 이 스킬이 아니라 `docs/publishing-plan.md`의
메커니즘과 mainmanager가 담당한다.

## 0. 전제: HyperFrames 연결 확인

이 저장소는 로컬에서 HyperFrames(별도 로컬 프로젝트 `claude_pro`에 있는
`hyperframes`·`hyperframes-core`·`hyperframes-animation`·`hyperframes-keyframes`·
`hyperframes-creative`·`hyperframes-cli`·`hyperframes-registry` 7개 스킬)를 윈도우
디렉터리 정션으로 `.claude/skills/`에 연결해서 쓴다 — 파일을 복사하지 않고 경로로만
참조한다(최초 1회 설정: [docs/local-hyperframes-setup.md](../../../docs/local-hyperframes-setup.md)).
§4(렌더링)로 넘어가기 전에 `.claude/skills/hyperframes/SKILL.md`가 실제로 열리는지
확인한다 — 안 열리면 정션이 깨진 것이니 그 문서대로 먼저 다시 연결한다.

## 1. 착수 조건

mainmanager의 "결과물 보고 및 승인 게이트"(`docs/mainmanager-plan.md` §6)를 통과한
후에만 착수한다 — 사용자가 "카드뉴스·숏츠 스토리보드 작성으로 진행할까요?"에 승인한
경우. 승인 전에는 착수하지 않는다.

입력은 승인된 그 주 블로그 원고 폴더(`<번호>_<주제요약>/블로그/`, `content-playbook.md`
§11 구조)다 — 카드뉴스·숏츠는 항상 그 주 블로그 원고에서 소재를 뽑아 파생 제작한다
(카드뉴스 전용 별도 기획안은 운영하지 않음).

## 2. 스토리보드·캡션·스레드 작성

`content-playbook.md`의 아래 규칙을 그대로 따른다 — 이 스킬이 새 규칙을 만들지
않는다:

1. **카드뉴스 스토리보드**(§5) — 9~10장·1080×1350, 표지→반전/문제제기→데이터→
   비교·차트→근거→해결책→체크리스트→CTA 순서, 상단 모션그래픽+하단 본문 각각 작성,
   문서 상단 메타정보·맨 아래 "확인이 필요한 부분" 섹션 필수.
   저장: `카드뉴스/카드뉴스_스토리보드.md`
2. **숏츠·릴스 스토리보드**(§6) — 1080×1920·20~30초(6~7장면), 1순위(카드뉴스 기반)
   /2순위(구글 플로우 Veo 아바타, 원장 등장이 필요할 때만) 중 방식 결정.
   저장: `숏츠/숏츠_스토리보드.md`
3. **온스크린 CTA**(§7) — 오프닝 3초·중반·클로징 총 3회 노출 타이밍, KittyChat
   댓글→DM 자동화가 켜져 있는지 확인 후 문구 확정(꺼져 있으면 대체 문구).
4. **채널별 캡션**(§8) — 채널별 글자수 한도·클릭 전 노출 구간·마스터 캡션 구조·
   하이퍼로컬 타겟팅(6개 학교) 규칙대로 작성 후 실제 글자수 확인.
   저장: `카드뉴스/채널별_캡션.md`, `숏츠/채널별_캡션.md`, `숏츠/캡션_유튜브쇼츠.md`,
   `숏츠/네이버클립_소개글.md`
5. **스레드 초안**(§9) — 500자 이내(권장 50~150자), 답글 유도 질문형 마무리, 미디어는
   그 주 상황에 맞게 ①텍스트+네이버 블로그 링크만 또는 ②카드뉴스 캐러셀 첨부 중
   하나(2026-09-09 변경, 기존 "카드뉴스 표지 1장→4:5 영상" 우선순위는 폐기).
   **§8 "블로그 원문 링크" 규칙상 스레드도
   직접 링크 가능 채널이라 `📝 원문 보기 👉 {{BLOG_URL}}` 한 줄이 반드시 들어가야
   한다**(2026-09-08 36주차에서 이 줄이 통째로 빠져 있던 걸 뒤늦게 발견 — 초안
   작성 시점엔 블로그가 아직 발행 전이라 실제 URL을 모르니 `{{BLOG_URL}}` placeholder
   그대로 적어두고, 화요일 블로그 발행 후 §8 규칙대로 실제 URL로 채워 넣는다).
   저장: `스레드.md`

작성 완료 후 §11 규칙대로 `카드뉴스_발행현황.md`·`나인플러스_콘텐츠_인덱스.md`를
갱신한다.

## 3. 렌더링 착수 전 사용자 확인

스토리보드·캡션·스레드 초안이 완성되면, **렌더링(실제 이미지/영상 생성)으로
넘어가기 전에 반드시** 다음을 보고하고 승인을 받는다 — 승인 없이 §4로 진행하지
않는다:

- 스토리보드 요약(장면 수·핵심 문구·CTA 위치)
- "확인이 필요한 부분" 섹션 내용(원고에 없는데 스토리보드가 임의로 추가/해석한 지점)
- 숏츠 제작 방식(1순위 카드뉴스 기반 vs 2순위 Veo 아바타) 확정
- 사용자가 범위를 좁히면(예: "숏츠만") 그 범위만 진행한다.

## 4. 렌더링 (HyperFrames 핸드오프)

승인 후 `/hyperframes` 진입점 스킬을 그대로 호출한다:

- 카드뉴스(정지 이미지 9장 + 컷 전환 몽타주)와 숏츠(9:16 20~30초)는 둘 다
  `/general-video`(컴패니언 모드) 워크플로에 해당한다 — HyperFrames의 표준 라우팅
  표에 "카드뉴스" 항목이 따로 없는 건 그 표가 완성될 영상의 성격(광고·설명형·자막·
  PR·모션그래픽 등)으로 나뉘어 있기 때문이고, 자유형 멀티씬 구성인 카드뉴스·숏츠는
  항상 general-video다.
- HyperFrames의 `references/intent-interview.md` 기반 질문은 §2에서 이미 스토리보드로
  답을 다 만들어뒀으므로, 스토리보드 내용을 그대로 브리핑 삼아 넘긴다 — 처음부터
  다시 인터뷰하지 않는다.
- 필요한 실제 미디어(사진·아이콘·음원 등)는 `content-playbook.md` §3 이미지 규칙과
  §11 폴더 구조를 따라 준비해 HyperFrames에 넘긴다.
- 결과물 저장 위치(§11 그대로): 카드뉴스는 `instagram/01~09.png`+`facebook/01~09.png`
  (각각 `_원본프로젝트_instagram/`·`_원본프로젝트_facebook/`, 페이스북도 캐러셀
  9장 전체를 씬별로 캡처 — 2026-09-08 표지 1장에서 전환), 숏츠는
  `9x16_instagram.mp4`·`9x16_facebook.mp4`·`9x16_youtube.mp4`(+ 4:5 보조 버전,
  `_원본프로젝트_916_instagram/`·`_원본프로젝트_916_facebook/`·
  `_원본프로젝트_916_youtube/`·`_원본프로젝트_4x5/`) — 온스크린 CTA가 채널마다
  달라서(§2-3, content-playbook.md §7) 하나의 파일을 여러 채널이 공유하지 않는다.

## 5. 렌더링 후 마무리

1. 완성 파일(PNG 9장, mp4)을 확인하고 채널별 캡션을 최종 확정(§8 규칙으로 실제
   글자수 재확인).
2. `카드뉴스_발행현황.md`·`나인플러스_콘텐츠_인덱스.md` 갱신.
3. 완성 결과물을 사용자에게 보고한다 — 이후는 `docs/publishing-plan.md`의 콘텐츠 큐
   절차(발행 직전 `queue/`로 복사)로 넘어간다. **이 스킬은 발행 자체를 수행하지
   않는다.**

## 원칙

- §4(렌더링)는 항상 §3 사용자 승인 이후에만 진행한다.
- 스토리보드·캡션·스레드 문구는 `content-playbook.md`를 벗어나 임의로 새 규칙을
  만들지 않는다 — 규칙과 실제 원고 사이에 애매한 지점이 생기면 "확인이 필요한
  부분"에 적어 사용자 판단에 맡긴다.
- 실제 결과물(스토리보드·이미지·영상)은 이 저장소(`others`)에 두지 않는다 — 로컬
  작업 폴더에만 보관하고, 발행 직전에만 `queue/`로 잠깐 복사한다(콘텐츠 저장 원칙).
